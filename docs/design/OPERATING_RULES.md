# OPERATING_RULES.md — AI間の指示・承認・停止・品質・監査ルール

状態: DRAFT（最終更新 2026-11-02）

## 1. 指示系統
- 社長 → AI COO → 部長 AI → 係担当 AI の順に案件・タスクを割り当てる。係担当 AI 同士の引継ぎは共通DBのタスクレコード経由とする。
- AI COO は人間に「確認待ち案件・必要書類・推奨対応」を共有キューで通知する。業務委託者への契約上の依頼、優先順位変更、報酬・稼働条件の変更は社長または契約上の権限者のみが行う。
- 会話履歴を正本にしない。引継ぎ情報は案件ID・タスク・成果物・版数で共通DBに保存する。

## 2. リスク3区分と取扱い
| 区分 | 例 | 取扱い |
|---|---|---|
| 低 | 公知情報収集、内部草案、資料整理 | 許可された手順で自動実行 |
| 中 | 承認済み宛先・媒体・予算内の定型運用 | 事前設定条件内で自動化し監視 |
| 高 | 契約、発注、新規支出、重要提案、権限拡大、本番反映 | 人間担当が事前確認 → 社長決裁 |

## 3. 人間の承認が必須の行為
契約締結・発注・新規支出／顧客への確約・値引き・契約条件変更／重要な対外送信／権限の付与・拡大／AI社員の本番反映／顧客秘密情報の取扱い開始。

## 4. 人間チェックポイント
| フェーズ | 人間の関与 |
|---|---|
| 営業・提案 | 営業担当が商談、社長が重要条件を承認 |
| サービス開発 | 事業開発・品質担当が価値・手法を検証 |
| 受注・実行準備 | PM担当が外注調整、社長が契約・発注を承認 |
| 制作・運用 | PM担当が仕様・納期、品質担当が重要納品物確認 |
| 検収・請求 | PM担当が検収窓口、総務担当が金額・証憑照合 |
| 契約更新 | 営業担当が継続協議、社長が重要契約を決裁 |

## 5. 停止・安全機構
- 処理ごとの支出上限・実行時間上限・再試行回数上限を必須設定（無限ループ防止）。
- 異常検知時は当該エージェントを自動停止し、AI COO と社長の共有キューへ通知。
- 各AIは最小権限。送信前チェック、予算上限、異常時停止、復元手順を持つ。
- 社長不在時の緊急停止権限者を契約で事前に定める。

## 6. 品質・監査
- 独立監査: 経営管理部 品質・リスク管理課が AI 検査。分析部門のセルフチェックと分離する。
- AIV・需要分析は、測定条件・対象AI・日時・設問・言語、外部データの実測／推計区分を保存する。
- 提案書・レポートは、根拠資料・数値・主張・契約仕様との一致を別 AI がチェックする。
- 事業開発・品質担当が開発に関与した新手法は、重要案件で外部専門家が独立レビューする。
- 重大な問題は社長に直接報告する。
- 禁止: データ・出典の捏造、成果の保証表現、実測値と推計値の混同。

## 7. 外部送信・顧客データ
- 営業メールは適法性・配信停止・重複排除を管理する。
- GBP・広告・SNS は顧客の権限・同意と承認済み運用ルールの範囲に限定する。
- 顧客秘密情報を扱う前に、契約・プライバシー・保存期間・アクセス制御を確認する。

## 8. 監査ログ（必須記録）
出典、AIモデル、作業版数、操作記録、承認者、送信・支出履歴、コスト（案件ID単位）。

## 9. 新サービス追加時
登録 → 既存係で担えるか・収益性・負荷を評価 → AI COO が兼務／新係／課再編を提案 → 社長が改編と新規支出を承認 → AIシステム部が試験・導入 → KPIで継続評価。
