**試験項目**
| ID | 項目 | 合格基準 |
|---|---|---|
| T2-01 | 案件登録後、人が指示しなくてもダミー工程 A→B が完了する | 都度指示なしで完了 |
| T2-02 | 引継ぎで欠落・重複がない（同一案件の二重登録・同一タスクの二重起動） | 結果が 1 件のみ |
| T2-03 | 高リスク操作は承認前にブロックされる（承認なし・期限切れ・内容変更後の承認） | すべて実行されない |
| T2-04 | 再試行が上限で止まり人間キューに載る | 無限ループしない |
| T2-05 | 費用・実行時間の上限で停止し記録が残る | 停止と記録を確認 |
| T2-06 | 上限未設定の役割・案件は起動しない（fail closed） | 起動しない |
| T2-07 | 緊急停止（全体・部・役割・案件）が効き、再開は人間のみ | 停止が効き、AI は再開できない |
| T2-08 | 連続失敗で役割が自動停止（サーキットブレーカー） | 閾値で停止し通知 |
| T2-09 | 異常時に障害ログと切り戻し案が人間キューに届く | 届く |
| T2-10 | 案件ごとの API 費用を追跡できる | cost_ledger で集計できる |
| T2-11 | 新しいダミー役割を台帳に追加し、既存基盤で動かせる | 基盤の変更なしで動く |
| T2-12 | AI COO が承認結果を書込めず、人間への契約上の指示を出さない | 権限テストで拒否される |
| T2-13 | 権限のない主体は他のデータを読めない（RLS） | 拒否される |
| T2-14 | バックアップから復元できる | 手順書どおり復元できる |

**完成基準**: 登録後は各 AI への都度指示なしで工程が進む／引継ぎでデータ欠落・重複処理なし／人間承認前の重要操作を禁止できる／停止・再試行・復旧の記録と実行が可能／案件ごとの API・実行コストを追跡できる／新たな AI 役割を既存基盤に追加できる。

| 人間側確認待ちがボトルネック | 確認キューの上限・優先度ルール、関与時間を計測 |
