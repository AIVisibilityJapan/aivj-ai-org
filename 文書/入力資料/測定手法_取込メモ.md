|---|---|---|
| 何を測るか | 自治体を対戦形式で比較し、AI 評価を順位化 | AI に旅行先を聞いたとき、rank1〜3 に自治体が出る割合 |

| 規模 | 16 区分、比較 494,502 件 | 質問 14,592 件（57 範囲 × 256 質問）、8 カテゴリ |

| 解釈の注意 | 来訪者数・消費額・満足度ではない | 観光価値そのものではない。0% は資源がないことを意味しない |

## 2. 共通する運用原則（AI 組織の設計にそのまま関係するもの）
1. **正式測定結果は凍結**（順位・勝敗・理由・Raw・出現数・出現率）。上書き・削除・移動・名称変更をしない。回収は copy-only。
2. **改善は新 version で追加**（append-only）。既存 version を直接上書きしない。再計算が要る条件は明確に限定されている。
3. **version と SHA を固定して参照**。「最新を自動探索」はしない。不一致なら停止（fail-closed）。
4. **2 つの対象集合（1,719 / 1,741）は別物**。件数や名称の一致だけで結合しない。
5. **0% と欠損を区別**（EXPLICIT_ZERO / NO_FORMAL_ROW / NOT_APPLICABLE / NOT_AVAILABLE）。欠損を 0% にしない。
6. **件数は集計単位を明示**（文字列一致 / 理由文単位 / canonical 統合後）。
7. **推測で補完しない**（別区分の条件を同一と推測しない、名称が似ているだけで同一視しない、外部情報だけで資源を追加しない）。
8. **診断レポート生成前に Preflight を実行**し、未解決があれば停止。確定できないものは保留のまま維持する。
9. 出現率と APA は名前空間を分け、**生成層／selector 層で統合**する。レポート側で独自に再結合・独自スコアで選び直さない。

これらは本組織の設計方針（fail closed、承認はハッシュ固定、測定値・推計値・不明点の区別）と整合している。
