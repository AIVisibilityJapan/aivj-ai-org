# バックアップと復元の手順（T2-14）

対象: 実行状態（`データ\実行状態\`＝タスク・承認・停止・費用の記録）、`設定\担当者\`（Git に載らない担当者台帳）。
オプションで `データ\private\`（顧客別・受領資料・自社資料。顧客情報を含む）。
道具: `scripts/backup_state.py`（標準ライブラリのみ。外部へは送らない）。

## 1. バックアップを取る
```powershell
cd C:\dev\aivj-ai-org
py scripts/backup_state.py backup --dest C:\aivj_backup
py scripts/backup_state.py backup --dest C:\aivj_backup --with-private
```
- `C:\aivj_backup` は例です。保存先は必ず指定します（存在しないドライブは使えません。`Get-PSDrive -PSProvider FileSystem` で使えるドライブを確認）。PowerShell では `<` `>` は使えないため、zip の名前は実際の名前に置き換えます。リポジトリの中は拒否されます（Git に載るのを防ぐため）。
- zip は暗号化されません。**保存先は、本人しか開けない場所**（権限を絞ったフォルダ、BitLocker 等で暗号化したドライブ）にしてください。OneDrive 等の同期フォルダは避けてください。
- zip 内の台帳（manifest.json）に、全ファイルの SHA-256 を記録します。
- `--with-private` は、大容量の `データ\private\05-測定データ`（測定データのコピー）を含めません（元データが別にあるため）。含めたいときだけ `--with-measurement` を付けます（zip が巨大になります）。測定データは、元の場所と SHA-256 の記録（`データ\測定データ参照.md`）で守ります。
- 頻度の目安: 実行状態は、作業をした日の終わりに 1 回。private は、資料を追加したとき。

## 2. 壊れていないか確認する
```powershell
py scripts/backup_state.py verify --file C:\aivj_backup\（作られた zip の名前）.zip
```
「問題ありません: N ファイル」と出れば OK。台帳との不一致（改ざん・破損・追加・欠落）は、エラーで止まります。

## 3. 復元する
```powershell
py scripts/backup_state.py restore --file C:\aivj_backup\（作られた zip の名前）.zip --to C:\dev\restore_test
```
- 復元先は、**存在しないか空のフォルダ**にします。現在の実行状態を直接上書きしません。
- 復元後に全ファイルを再照合します。1 つでも違えば、エラーで止まります。
- 復元したフォルダの中身を確認してから、必要な分を元の場所へ置き換えます（置き換えは人が行います）。
  - 実行状態を戻す場合は、**先に現在の `データ\実行状態` を別の名前に退避**してから、復元した `データ\実行状態` を置きます。
  - 戻したあと、`py scripts/stop_control.py status` で停止状態を確認します（停止が残っているのが正常な場合があります）。
  - 管理画面（`py src/admin-ui/build_dashboard.py`）で、件数と状態を目で確認します。

## 4. 復元の訓練（年 1 回、または仕組みを変えたとき）
1. バックアップを取る → 2. verify → 3. 別フォルダへ restore → 4. 中身の件数を管理画面で確認 → 5. 試験用フォルダを削除。

## 切り戻し（誤った操作・誤った変更を戻したいとき）
- コード・文書: Git の履歴から戻します（`git log` で確認し、戻す前に社長が確認）。
- 実行状態: 上の復元。復元元は、直前のバックアップ。
- 承認・停止の記録は追記専用（`承認記録.jsonl`、`停止ログ.jsonl`）です。消さずに、新しい記録で訂正します。
