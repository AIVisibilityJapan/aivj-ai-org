# 本番反映手順（新しい AI 役割の登録）

状態: 案（社長確認前）。STEP 2 のタスクエンジン・承認キュー完成までは手動で行う。

## 原則
- 本番反映（main への反映・役割の登録）と権限付与は、社長の承認が必須（D-015）。
- AI-07-01 は main に直接反映しない。開発ブランチと別フォルダまで。
- 承認は承認依頼書の内容ハッシュに結び付ける。承認後に内容が変わったら無効。
- 費用が発生する処理は、実行前に社長が確認する（D-019）。

## 手順
1. 要件受付: 業務要件（テンプレート/業務要件_仮様式.md）を社長がチャットに貼る
2. 作成: AI-07-01 が role.yaml 案、テスト計画、承認依頼書を作成（チャット上）
3. 別フォルダで模擬実行（ダミーデータのみ）。結果を試験項目と照合
4. 台帳検証: `python scripts/validate_roles.py` が通ることを確認
5. 承認依頼: 承認依頼書（変更内容、リスク段階、権限、試験結果、内容ハッシュ）を社長へ提示
6. 社長が判断: 承認／却下／修正依頼。結果を承認ログに記録
7. 反映（承認後のみ）: 台帳・role.yaml を更新して push。反映作業は、AI-07-03 稼働前は社長が実行（コマンドは Claude が用意）
8. 反映後確認: 台帳検証と単体試験が通ることを確認。判断ログに記録

## 却下・失敗時
- 却下: 理由を承認ログに記録。本番側は変更しない
- 試験が再試行上限（2 回）を超えて失敗: 停止して社長へ報告。原因を記録
