# チャット運用と初回指示（案）

作成: 2026-11-09 / 状態: 案（社長確認前）/ 正本: このファイル（リポジトリ `文書/手順書/`）。プロジェクト「AIVJ全体」にも同じ内容を置く。

## 1. 基本方針
- **リポジトリは 1 つ**: `C:\dev\aivj-ai-org`（GitHub: AIVisibilityJapan/aivj-ai-org）。チャットごとに別リポジトリは作らない。違いは「作業するフォルダ」と「最初に読む文書」。
- **チャットは作業の流れ（ワークストリーム）ごと**。部門ごとではない。部門の実体は `src/AI社員/<部>/<役割>/role.yaml` で、AI COO が呼び出す。
- **引き継ぎは会話ではなくファイル**: 状態は 判断ログ・承認ログ・設計書・手順書・各文書の「更新履歴」に残す（CLAUDE.md）。チャットは節目（Git に保存した直後など）で切る。
- **独立監査は別チャット**: 作成側の推論や下書きを持ち込まず、成果物と根拠だけを渡す（AI-06-05/06 の独立性）。
- **私的データ**（`データ/private`）は Git に載せない。チャットの添付やプロジェクト資料にも増やさない。

## 3. 共通の初回指示（全チャットの先頭に貼る）
```
リポジトリは C:\dev\aivj-ai-org。最初に次を読み、守ってください。
1) CLAUDE.md、文書/設計/MASTER_PLAN.md、文書/設計/OPERATING_RULES.md
2) 契約・支出・重要な対外送信・権限変更・本番反映は、人間（社長）の承認なしに行わない
3) 既定は読み取り専用。正式データ・pointer・Gate・API・外部送信は、私の明示の指示があるときだけ。元データは開いて保存し直さない・移動も削除もしない
4) 「保存してください」と言うまで、commit も push もしない（保存の前に git status で対象を確認）
5) データ・出典を捏造しない。実測値・推計値・不明を区別する。確認できなかった≠存在しない≠不採用
6) 文書は複製せず同じファイルを更新し、末尾の更新履歴に追記する。判断は 文書/判断ログ/README.md、承認は 文書/承認ログ/README.md に時系列で追記する
7) 質問は 1 回に 1 つまで。作業を始める前に「これから何をするか」を 1 文で伝える
8) 終了時は、(a) 何を変えたか (b) 保存したか (c) 次の一手 を、文書の更新履歴かこのチャットの最後に残す
```
