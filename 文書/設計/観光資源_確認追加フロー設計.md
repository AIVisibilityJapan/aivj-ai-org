# 観光資源の確認・追加フロー 設計（AI 組織版）

状態: 案（2026-11-05。社長の指示 D-053 による。役割の割り当ては社長が了承済み。各役割の定義は『案』で承認待ち）
正本: 観光資源の原文再監査・正式採用・マスター反映フロー（原文: データ/private/05-測定データ/観光資源_原文再監査フロー_原文.txt。要点: 文書/入力資料/観光資源_原文再監査フロー_取込メモ.md）。**食い違いがあれば原文を優先してこの設計を直す。**

## 1. 目的
無償レポートの『出現を支える観光資源 Top3』が 3 件未満のとき、すぐ「―」にせず、測定の原文まで遡り、基準を満たす資源だけをマスターに正式追加して、レポートに反映できるようにする。判断できないもの・Alias 等の重複・基準に満たないものは追加しない。**3 枠を埋めることが目的ではない。**「―」は正式な診断結果になり得る。

## 2. 社長の指示（2026-11-05）
1. Top3 が 3 件に満たない場合は測定の原文まで遡る。
2. 判定できないものや、Alias のような重複・基準に満たないものを除き、正式に追加できるものはマスターに追加して、無償レポートに反映できるようにする。
3. 原文を遡る・資源が適切かを監査するなど、作業ごとに仕事を振り分ける（AI 組織の役割として動かす）。
4. **監査の後、資源を追加するときは確認する。**
5. マスターへの追記は AI（データ統制 AI）が社長の承認の後に実行する。公式サイトの読み取り（読み取りのみ・費用 0・公的・公式ドメインのみ・参照した URL を記録）は許可する。

## 4. 流れ（aiv-resource-review）
S0 現行の確認 → S1 候補の抽出 → S2 Evidence 確認と分類案 → S3 独立監査 → **S4 社長の確認①** → S5 追記 → S6 全国回帰と Gate 再判定 → S7 追記後の検証 → **S8 社長の確認②（current pointer）** → S9 pins.yaml の固定 → S10 レポート再生成。
- S0: 現行の formal pointer（Common Asset／Alias／APA mapping／selector／Gate／Source contract）の版・SHA・schema・行数を確認。合わなければ RESOURCE_COVERAGE_SOURCE_ERROR で止める。旧版へ勝手に fallback しない。
- S1: Appearance rank1〜5、APA の自治体自身の WIN 推薦理由原文を読む。具体名の候補を抽出（一般表現は GENERAL_EXPRESSION）。mention／mapping／selector との差分（7 種の gap）を出す。
- S2: 優先 Evidence は 自治体公式 → 都道府県公式 → 国・公的機関 → 観光協会公式 → 施設公式 → 公的観光情報。一般ブログ・口コミ・まとめサイトだけでは正式化しない。分類は 12 種で未分類を残さない。
- S3: SELF_VERIFIED_ACTIVE の条件（原文 §10 の 13 項目）を全部満たすものだけ『採用可』。NON_SELF・OPPONENT・一般表現・identity 不明・自治体関係不明・現役性不明・Evidence 不足・包括名と構成資産の関係不明は『除外』または『保留（REVIEW_REQUIRED）』。保留はレポートに出さない。
- S4: **採用可の一覧を社長が確認。承認がなければ追記しない。**
- S5: 新規 canonical は Common Asset へ、既存と同一なら Common Alias へ append。resource mention を補完し、APA mapping に接続し、selector の次版を Build（既存版は上書きしない）。Appearance の測定値・APA ランキングは変更しない。
- S6: 全国 1,741 自治体・5,223 枠が全て PASS、想定外の差分 0（wrong municipality・opponent・重複 Top3・unsafe relation・binding mismatch・lineage 欠落も 0）。Gate を再判定。
- S7: 分析監査 AI が結果を検証（想定内の差分は今回追加した資源だけ）。
- S8〜S10: current pointer 切替（社長が承認）→ pins.yaml を固定し直す（判断ログに記録）→ 無償レポートを再生成（selector の出力と完全一致。PPTX で独自に資源を選ばない）。生成後の QA は監査 AI（文字・数値）、Visual QA と PowerPoint 標準の PDF 書き出しは人。

## 5. 守る原則（原文 §40・§44）
- レポート（PPTX）に資源を直接書き足さない。正式経路: 測定原文 → 候補 → Evidence → Common Asset／Alias → mention → APA mapping → selector → レポート。
- 公式サイトにあるという理由だけで測定外の資源を追加しない。他自治体の資源を近いという理由で採用しない。REVIEW_REQUIRED を勝手に正式化しない。
- 3 枠を埋めるための推測補完をしない。旧称と新称を別 slot にしない。包括名称と構成資産を重複表示しない。
- 現行の formal を確認せず古い版を使わない。source error のときの silent fallback をしない。
- 追記は append-only。既存の正式版は上書き・削除・移動・名称変更をしない。旧版は rollback 用に保持。

## 6. 安全策（fail closed）
- データ統制 AI は、**追記専用の道具と全国回帰の道具が未作成**の間は実行しない。作成後も、まず作業用コピーで試験し、結果を社長が確認してから初回の実行をする。
- 社長の確認①が記録されていない追加案は実行しない。
- 追記と pointer 切替の間に、全国回帰の想定外の差分が 1 件でもあれば、正式化しない。
- 公式サイトは読み取りのみ。公的・公式ドメインに限り、参照した URL・該当箇所・取得日を Evidence に残す。
- 費用は 0（API を使わない）。上限は 設定/budgets.yaml。
