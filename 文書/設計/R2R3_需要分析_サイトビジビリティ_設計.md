## 4. 値の状態と表示（R1 と共通）
R1 設計書 §3 の状態をそのまま使う。加えて、値ごとに**性質（basis）**を持たせる。

| 状態 | 意味 | 表示 |
|---|---|---|
| VALUE | 取得した正式データから導出した値 | 値 |
| INSUFFICIENT_SAMPLE | 標本が 30 件未満 | 「—」 |
| NOT_MEASURED | 取得していない（未契約の枠・未実施の AI・過去期など） | 「—」 |
| NOT_APPLICABLE／NOT_AVAILABLE | 該当なし／取れない | 「—」（0 にしない） |

| 性質（basis） | 例 |
|---|---|
| MEASURED（実測） | 標本の質問数、取得した出典の件数 |
| ESTIMATE（推計） | AI ボリューム（トピック単位の月間推計）。「件数」と言い切らず「AI ボリューム」「推計」と書く |
| RELATIVE（相対値） | `volume_trend`（各トピックの最大 = 100）。絶対値に換算しない |
| UNKNOWN（不明） | 月の対応が分からない列など |

- ②の 2 つの指標（AI Overviews の表示回数／対話型 AI への質問数）は足し合わせない。
- 「—」の意味は本文に書き足さず、別紙の対応表（スロットごとの状態・理由）で管理する。

- 項目: 取得 ID・日時・操作者・機能・画面の条件（DB・AI・検索語）・件数・元ファイル名・保存名・SHA-256・サイズ・その日の書き出し通算・状態・性質・備考。
- 追記のみ。行を書き換えない（訂正は新しい行）。測定条件・対象 AI・日時・検索語は OPERATING_RULES §6 の保存項目。

### 5.3 保存場所とファイル名
```
データ/private/07-R2R3作業/<自治体ID>/
  自治体設定.yaml
  取得ログ.csv
  元データ/    ← 取得した CSV のコピー（追記のみ・読み取り専用。元は Downloads に残す）
  値ファイル/  ← スロットごとの値・状態・性質・母数・出所（SHA）
  出力/        ← 試作レポート
```
- 元データのファイル名: `R2_<自治体ID>_<対象年月>_<指標>_<AI>_<検索語番号>_取得<YYYYMMDD>.csv`（③は `R3_…`）。指標・AI・検索語番号は設定ファイルの値と対応させる。
- ブラウザが付ける既定名（`topics_by_fts____jp.csv`）は、取得ログの「元ファイル名」に残し、コピー時に上の名前にする。元ファイルは移動も削除もしない。

### 5.4 取得の制約と運用
- 書き出しは **1 日 10 件まで**。1 自治体の②は「検索語 × AI（AI Overviews とそれ以外は別取得）」の数だけ要るため、取得計画に日ごとの割り振りを持たせる。
- ブラウザ操作の標準（原本 §5-4）: 設定変更をしない／ページへスクリプトを入れない／1 件ずつ間隔を空けて書き出し、保存を確認する／取得日時を記録する／1 セッション 14 件程度に分ける／利用規約上の自動操作の可否は人が再確認する。
- 社長がブラウザでログイン済みであること。Claude はログイン・パスワード入力をしない。
- 書き出し・ドメイン登録・プロンプト追跡の登録（「監視する」）は、そのつど承認を得る。

### 5.5 スロットと値ファイル（R1 と同じ方式）
- スロット ID: `表番号.行.列`、`図番号.系列.点`、`本文 ID`。②は青凪町版の表・図、③は白浜 v32 の表・図に対応させる（ID の割り当ては見本 PDF と原本付録 A から作る。実装時）。
- 値ファイル: 各スロットに value・status・basis・単位・母数（n）・出所（元データの保存名と SHA）を持たせる。
- レンダラは値を計算せず、状態が VALUE 以外なら「—」を入れる。R1 のレンダラと体裁部品を共用する。
- 参照する元データの版・SHA を値ファイルの先頭に固定する。不一致なら停止（fail closed）。「最新を自動探索」しない。
