# 資源追記ツール 設計書（案・実装前）

作成日: 2026-11-09 / 状態: 案（実装しない。社長確認前）
型紙: `build_append9.py`（1.5.50→1.5.51、REPRO_PASS 済み）。補助: `build_resources_s1550.py`（Batch38、1.5.49→1.5.50）。

## 1. 目的と範囲
承認済みの資源候補（根拠確認・独立監査・社長確認①を通過したもの）を、現行の Common Asset / Alias / relation / APA mapping / selector スロットへ**追記専用**で反映した「次版」を、**一時フォルダ（stage）にだけ**作る。正式 pointer の切替、Gate 更新、PPTX 再生成は対象外（別工程・社長確認②）。

## 2. 既存ビルダーから分かった型（型紙）
1. 入力版の固定: 旧パッケージ一式（master / alias / relation / Appearance mapping / candidate mapping / APA mapping / lineage / slots）を読む。
2. 追記指定（SPECS）: 自治体ID、正規名、subtype、scope、relation_type、公式根拠URL、根拠となる測定記録（APA の comparison_id、または Appearance 候補）。
3. 資産の再利用判定: 正規名が既存マスターに1件ならそれを再利用、複数なら中断、無ければ新規ID（`prefix + sha256(mid|name)`）。
4. 追記: master（新規のみ）、relation、APA mapping（identity 行）、lineage（原文一致の行）。旧行は全て保持。
5. 根拠検査: 正規名が測定原文に含まれなければ中断（append9）。
6. スロット: append9 は空スロットだけを埋める。Batch38 は自治体ごとの並べ方を直書きして入れ替える。
7. 回帰検査（内蔵）: 1,741自治体・5,223枠、同一自治体内の重複0、unsafe 0、優先順位違反0、期待分布。
8. 出力: 新版パッケージ、pin / pointer / binding の stage 版、manifest、検証サマリー。

## 3. 既存の弱点（新ツールで直す点）
- SPECS・版番号・分布の期待値・日時（NOW）がコードに直書き。
- 入力パスが旧PCの絶対パス（Batch38）。
- 追記先が「空スロットのみ」。既存資源がある自治体への優先順位に沿った挿入は、直書きの並べ替えに頼っている。
- 検査が失敗すると例外で止まるだけで、不一致の理由の一覧が残らない。

## 4. 新ツールの仕様案
### 入力（全て引数。自動探索なし）
- `--baseline-root`: 現行パッケージ一式（pin の SHA と照合。不一致なら停止）
- `--spec-file`: 追記指定CSV（1行=1資源・1自治体）
- `--apa-sqlite` / `--appearance-sqlite`: 読み取り専用（`mode=ro`、SHA 照合）
- `--stage-root`: 存在しない新規フォルダ（既存なら停止。rmtree しない）
- `--now`: 実行日時（再現性のため明示）

### 追記指定CSVの列
municipality_id / canonical_name / subtype / resource_scope / relation_type / official_evidence_url / evidence_kind（APA_REASON | APPEARANCE_CANDIDATE）/ source_record_ids（comparison_id または candidate id）/ audit_ref（独立監査の記録番号）/ president_confirmation_ref

### 処理規則
- 採用順: Appearance 1–3位 → APA → Appearance 4–5位 → 「―」。測定原文に具体名が無い資源（公式サイトのみで発見）は、参考候補として別CSVに分け、スロットには入れない。
- 重複排除は Common Asset ID。alias は同一資源として扱う。unsafe（NON_SELF / 閉鎖 / 未検証）は除外。
- 追記専用: 旧行は完全保持、ID衝突0、canonical重複0、alias衝突0、relation矛盾0、lineage欠落0。
- スロット更新は、(a) 空スロットの充填と、(b) 優先順位に従った並べ替えの2モードに分け、(b) は差分を全件出力して停止（人の承認待ち）とする。

### 出力
新版パッケージ、stage 版 pin / pointer / binding、expected_diff.csv（変わる枠の全件）、validation.json、manifest（全ファイルの SHA）、未採用候補と理由の一覧。

## 5. 検証（実装時の必須条件）
1. **ゴールデンテスト**: append9 の SPECS を追記指定CSVに起こし、1.5.50 から実行 → 1.5.51 と完全一致（現行の REPRO_PASS と同じ基準）。
2. 同様に Batch38 の3自治体で 1.5.49→1.5.50（入力が揃った場合）。
3. 否定テスト: 正規名が原文に無い、ID衝突、既存スロット上書き、pin の SHA 不一致で、それぞれ停止すること。
4. 実行前後で baseline の SHA が不変（変更0）。
5. 独立監査（AI-06-05）が結果を原文抜粋つきで確認。
