## 3. 値の状態と表示
Mart の状態列（EXPLICIT_ZERO・NO_FORMAL_ROW・NOT_APPLICABLE・NOT_AVAILABLE）に、R1 用の 2 状態を加える。

| 状態 | 意味 | 表示 |
|---|---|---|
| VALUE | 正式データから導出した値 | 値 |
| EXPLICIT_ZERO | 測定した結果が 0 | 0.0%（固定文面は FMT v2.24 と同じ扱い。「資源がない」「AI に認識されていない」と読める文を書かない） |
| INSUFFICIENT_SAMPLE | 標本が 30 件未満 | 「—」 |
| NOT_MEASURED | 測定を行っていない（Gemini・Claude・スポット APA・過去期） | 「—」 |
| NOT_APPLICABLE／NOT_AVAILABLE／NO_FORMAL_ROW | 既存の定義どおり | 「—」（0% にしない） |

- 「—」の意味は、本文に書き足さず、**別紙の対応表**（スロットごとの状態・理由）で管理する。レポートのフォーマットは変えない。
- 状態が VALUE でない欄の値を使って、所見・総括・改善提案の本文に数値を書かない。所見の扱いは §7 の確認事項。

## 4. 当てはめの作り（スロット）
- **スロット ID**: `表番号.行.列`、`図番号.系列.点`、`本文ID`（例: `T006.温泉.全国`）。ID は雪嶺村版の表 1〜136・図 1〜15・各ページの本文欄に対応させる。
- **値ファイル（1 自治体 1 ファイル）**: 各スロットに、value・status・単位・母数（n）・出所（Mart の表名・版・SHA）を持たせる。
- **版と SHA の固定**: 値ファイルの先頭に、参照した Mart・Common Asset・Gate などの版と SHA を記録する。不一致なら停止（fail closed）。「最新を自動探索」しない。
- **解除条件の台帳**: 状態が NOT_MEASURED／INSUFFICIENT_SAMPLE のスロット群に、「何が揃えば VALUE にできるか」を 1 行で持たせる（§5）。データが追加されたら、台帳を見て該当スロットだけを再導出する。
- **レンダラ**: 値ファイルを読み、テンプレート（雪嶺村版と同じ体裁）に当てはめるだけにする。レンダラは値を計算しない。状態が VALUE 以外なら「—」を入れる。

5. **T5 資源の集計と寄与マップ**: 実在確認ゲートつき。
