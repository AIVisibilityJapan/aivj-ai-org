# R1 / T1 値取り出し 実装設計

状態: 実装済み・受入確認済み（2026-11-17。scripts/aiv_r1_values.py、受入確認 scripts/aiv_r1_values_accept38.py）。作成: 2026-11-15。上位設計: `R1_地域ビジビリティ_設計.md`（§3 値の状態、§4 スロット、§5 データ群、§6 道具）。
対象: 正式データから、1 自治体分の「値ファイル」（スロットごとの値・状態・出所）を作る道具。レポートの組立（T6）・分類（T4）・文章（T8）はこの道具の範囲外。

## 1. 守ること（既存の取り決めの再掲）
- 正式データ（Mart・Common Asset・Alias・APA mapping・selector・pointer・Gate）は**読み取り専用**。書き込み・移動・削除・保存し直しをしない。再測定・API 実行・外部送信をしない。
- 版と SHA を固定して参照する。「最新を自動探索」しない。不一致なら停止（fail closed）。
- 実測値・推計値・不明を区別する。欠損を 0% にしない。確認できなかった≠存在しない≠不採用。
- 出現率（1,741 自治体）と APA（1,719 自治体）は別の対象集合。件数や名称の一致だけで結合しない。
- 既存ファイル（`aiv_make_free_report.py` など）は変更しない。新しい版名・新しいファイルで追加する。

## 2. 入力と固定（pin の解決）
1. 正式ルート `データ\private\05-測定データ\AIV_FORMAL_ROOT_20261114\AI Visibility` を引数で受ける。
2. 現行 pointer（`…/03_generated/config/resource_coverage_preflight_formal_current.json`）→ source contract（版は pointer の記載に従う。現行 1.1.12）の順に辿る。pointer の SHA、contract の SHA を照合する（`aiv_make_free_report.py` の `resolve_formal` と同じ手順）。
3. contract の `sources` から、次の論理名で**パスと SHA-256 を取る**（自動探索しない）:

| 論理名 | 用途 |
|---|---|
| `appearance_mart`（Report Mart v2.4） | 出現率の値、質問単位の表、資源の出現 |
| `apa_report_mart`（APA v1） | 順位、対戦、理由、ネガティブ |
| `diagnostic_selector_slots` | 観光資源 3 枠（無償レポートと同じ） |
| `gate_municipality_status` | Gate 判定 |
| `common_asset_master`／`common_municipality_relation` | 資源名の種別・自治体との関係・検証状態（T5 に渡す） |

4. 各ファイルは実測 SHA を照合してから開く（Mart は 135MB と 1.8GB。1 回の実行で 1 度だけ計算する）。開くときは `mode=ro&immutable=1`。
5. 実行の前後で、入力ファイルの SHA・更新日時・サイズが変わっていないことを確認する。
6. 出現率 Mart の `appearance_measurement`／`appearance_build_metadata`（測定の版、質問版、辞書・alias の版、対象件数 1,747／1,741／14,592）を値ファイルの先頭に写す。

## 3. 出力
場所: `データ/private/06-STEP4作業/R1/値ファイル/<自治体ID>_<日時>_<PID>/`（Git に載せない。既存フォルダには書かない。衝突したら停止）。

| ファイル | 内容 |

| `manifest.json` | 出力ファイルの SHA-256、入力の SHA、実行の引数、検証ゲートの結果 |

### G09 競合分析（`rankings`、`appearance_rate`、`municipality_comparisons`）
- **近接の採り方（社長決定 D-057）**: 出現率の分析は出現率の順位、APA の分析は APA の順位で、**該当自治体より順位が高い直近の自治体**を採る。1 位・2 位など上位が足りないときは、**順位が低い直近の自治体**で補う。
  - 順位の母集団は各 Mart のもの（出現率は報告対象 1,741、APA は 1,719）。評価区分・項目ごとに、その区分の順位で数える。
  - 採る件数は **上位側 3**（社長決定 D-058）。上位が足りない分だけ下位側から直近順に補う。
  - **直接対戦の有無に関わらず、順位だけで採る**（社長決定 D-058）。
  - **階層別**: 雪嶺村版の競合分析は階層別（台帳 表74〜89）のため、全国に加えブロック内・県内の順位でも同じ規則で採る（社長決定 D-058。レポートに必要な範囲）。
  - **出現率の順位（社長決定 D-060）**: 率の降順で順位を付け、同率は同順位（1・2・2・4 の数え方）。近接は「自分より率が**厳密に高い**自治体のうち、率が最も近いもの」から 3 件。同率の自治体が複数あるときは、APA の順位が上のものを先にする。上位が足りない（自分より率が高い自治体が 3 件未満）ときは、率が低い直近で補う。
  - **APA の順位**: `rankings` の順位（1〜1,719 の一意）をそのまま使う。自分自身は除く。
- 理由 = 自分と近接相手の**直接の対戦記録**（`municipality_comparisons` の `municipality_id`＋`opponent_id`＋`evaluation_id`）の `recommended_reason`／`not_recommended_reason`／`self_positive_reason`／`opponent_positive_reason` を、原文のまま `evidence/` に出す。要約・言い換えはしない（T8／人の作業）。
- 直接の対戦記録が無い近接相手は、理由欄だけ NO_FORMAL_ROW（「—」）とし、相手の名前と順位は残す（相手は順位で採るため）。P2・P5 の結果では、順位が隣り合う組の直接対戦は全体の約 14.6%（総合 68.8%、他の評価区分 5.9〜12.9%）で、総合以外の理由欄は大半が「—」になる見込み。
- 比較は Swiss／RR の `stage`・`round` ごとに複数行ありうる。T1 は全行を出し、選ぶのは後工程。

### G10 強み・弱み・ネガティブ（`reasons`、`negative_reasons`、`negative_summary`、`municipality_negative_summary`）
- **分類の方針（社長決定 D-058）**: その自治体に関するネガティブな理由のみを扱う。外部（他自治体）との比較で評価したもの、その他、自治体単体の評価として適切でないものは含めない。T1 は原文を出すだけで、この除外の判定は T4 で行う（除外した件数と理由を記録する）。
- 件数: `municipality_negative_summary.negative_reason_count_total_raw`（理由文単位）、評価区分ごとは `negative_summary`。集計単位（理由文単位）を `slot_status.csv` に明記する。サンプルの定義（「言及を含む回答の数」）とは違う。
- 理由文: 自治体の勝ち・負けの理由文を原文のまま `evidence/` に出す。分類（勝因・敗因・ネガティブ区分）は T4。
