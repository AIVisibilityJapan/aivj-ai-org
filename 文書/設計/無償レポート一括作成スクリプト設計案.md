# 無償レポート一括作成スクリプト 設計案

状態: **確定（社長決定 2026-11-20。§9）**。スクリプトを作成する。既存のツールと正式データは変更しない。
作成: 2026-11-20（社長指示「一回の指示でまとめて作れるように」「PowerShell の操作を最小に」）

## 1. 目的
- 自治体の無償診断レポート作成で、社長の PowerShell 操作を「各段階 1 行」にする。
- 実行結果の貼り付けをなくす（スクリプトが要約ファイルを書き、Claude が端末から読む）。
- 社長確認①②・承認番号・正式データの変更は自動化しない（approval-rules.yaml のとおり）。

## 2. 範囲
- 新規: `scripts/aiv_free_report_pipeline.py`、試験 `tests/`、使い方を `scripts/README.md` に追記。
- 呼び出す既存ツール（変更しない）: `aiv_extract_candidates_one_v3.py`、`aiv_gate_ledger_check.py`、`aiv_resource_append_v2.py`、`aiv_gate_release_stage.py`、`aiv_release_build.py`、`aiv_release_switch_v2.py`、`aiv_make_free_report.py`。
- 第 1 版は「空き枠への追記」だけに対応する。入れ替え・改名・別名（`aiv_resource_reorder_v1.py`）が要る自治体（福岡市型、笠置町の枠整理）は、第 2 版で対応する（それまでは、今の手順）。

## 3. 全体の流れ
| 段階 | 社長の操作 | 内容 | 本番を変えるか |
|---|---|---|---|
| A 候補抽出 | `py scripts\aiv_free_report_pipeline.py prepare --run-name 名前 --muni 自治体名:都道府県 …` | 現行の版・Gate・枠を読み、候補を抽出する。要約を出す | 変えない |
| （Claude） | なし | 要約を読み、独立監査・台帳・追記指定・解除指定・測定固有名詞を作る（今と同じ。保留は社長判断） | 変えない |
| B stage | `… stage --run 実行ID` | baseline を現行からコピー → ledger_check → 追記 stage を 2 回作って一致確認 → 差分の要約を出す | 変えない |
| 確認① | `… approve1 --run 実行ID`（承認番号は実行 ID フォルダの `承認番号.csv` に記入） | 承認番号を確認 → Gate 解除 stage → リリース構築 → 検証 → 切替の予行 → 要約を出す | 変えない |
| 確認② | `… approve2 --run 実行ID`（`承認番号.csv` の ref_switch に記入） | 切替の本実行 → 全自治体のレポート生成 → 自動検査 → 要約を出す | **変える（切替）** |

確認①②は別々の実行（3 回）。決まりの順序（①→構築→②）を守る（§9 Q1）。

## 4. 実行 ID と置き場
- 作業フォルダ: `データ/private/06-STEP4作業/資源確認/一括/{実行ID}/`（`state.json`＝段階の進行・版・SHA・承認番号。既存の出力は上書きしない）。
- 要約（社長・Claude が読む）: `データ/private/一時保存/一括_{実行ID}/要約_{段階}.md` と、検査用のレポートのコピー。浅い階層に置くので、Claude が端末から直接読める。
- 実行 ID の形式: `{日付}_{名前}`。同名があれば停止。

## 5. 止まる条件（どれか 1 つでも該当したら、その段階で止めて報告する）
1. 現行ポインタの版が、`state.json` の記録と違う（他の処理が入った）。
2. baseline の SHA が現行の正式ファイルと違う。
3. 台帳に「要確認」「保留」が 1 行でもある。ledger_check が解除可でない（Gate がすでに通過の自治体は C5 を対象外として扱い、理由を要約に書く）。
4. 追記 stage が PASS でない／2 回の出力が一致しない／`changed_outside_spec` が空でない／変更が指定した自治体以外に及ぶ。
5. Gate 解除 stage の `unexpected_changes` が 0 でない。
6. 検証（validate）・予行が PASS／ready でない。
7. 承認番号が空、形式（`2026第{回}{Q}-{6 桁}-{日付}(-{連番})`）が違う、対象自治体の数と合わない。
8. 出力先に同名ファイルがある（上書きしない。削除もしない）。
9. 本番の切替後の post_probe が OK でない（既存ツールの自動ロールバックに従い、要約に戻し方を書く）。

## 6. 自動検査（段階 10 の機械的な部分）
- pptx: 枚数、スピーカーノート 0 文字、作成者・最終更新者が空、`MUNI_` などの残りがない、自治体名・Report ID・発行日、枠の資源名が現行 selector の枠と一致。
- PDF: ページ数、他自治体の ID・個人名がない。
- 対象外: 数値（順位・出現率・ランキング）の再計算（§9 Q3。測定後にまとめて計算したマスターから抽出する運用のため不要）。文面の目視・枠のはみ出しの画像確認は、必要に応じて Claude が別に実施。

## 7. 変えないもの・守ること
- 正式データの変更は `approve2` の切替だけ。削除・上書きはしない。
- 承認番号は、社長が渡した値をそのまま使う。スクリプトは採番しない。
- シークレット・個人情報・顧客データを出力に入れない。
- 既存ツールは呼び出すだけで変更しない。旧システムは使わない。
